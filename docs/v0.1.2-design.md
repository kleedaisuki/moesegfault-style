# v0.1.2 visual design / 视觉设计

## Intent / 意图

Keep warm paper, ink, and berry as the visual identity. Add translucency, restrained motion, readable code, and composable conversation details without replacing established component defaults.

保留暖纸、墨色与莓红。新增透光表面、克制动效、易读代码与可组合消息细节，不替换已有组件默认行为。

## Decisions / 设计选择

| Area / 领域 | Decision / 决策 | Constraint / 约束 |
| --- | --- | --- |
| Glass / 玻璃 | Use existing theme tokens for warm and rose surfaces. / 暖色与莓色表面沿用主题令牌。 | Solid fallback must remain readable; do not animate blur. / 实色降级仍需可读；不动画化模糊。 |
| Motion / 动效 | One-shot entrance presets and explicit replay in the showcase. / 一次入场与显式重播。 | Respect reduced-motion; no infinite decorative showcase loops. / 尊重减少动态效果偏好；展示不使用无限装饰循环。 |
| Icons / 图标 | Reuse the original brand geometry and extracted sparkle. / 复用原始品牌几何与星芒。 | Decorative by default; label meaningful usage. / 默认装饰；有含义的用法需命名。 |
| Code / 代码 | Shared component-owned theme styles, locally bundled mono font. / 组件统一拥有主题样式，本地打包等宽字体。 | No fixed dark override in documentation CSS; scroll long lines inside the frame. / 文档 CSS 不强制深色；长行在框内滚动。 |
| Messages / 消息 | Compose quotation, attachment, status, avatar, and native action buttons. / 组合引用、附件、状态、头像和原生操作按钮。 | A local demo must not imply a real backend or delivery. / 本地演示不能暗示真实后端或投递。 |

## Evidence and limits / 依据与边界

- [W3C C39: prefers-reduced-motion](https://www.w3.org/WAI/WCAG21/Techniques/css/C39) documents suppressing non-essential motion using the operating-system preference. The showcase replay button never overrides this preference. / W3C 给出通过系统偏好抑制非必要动态效果的方案；展示页重播不覆盖该偏好。
- [WebKit: Introducing Backdrop Filters](https://webkit.org/blog/3632/introducing-backdrop-filters/) explains that backdrop filtering requires additional rendering passes. Glass is therefore local and static, not a viewport-wide animated effect. This is a design constraint, not a measured performance claim for this release. / WebKit 说明背景过滤需要额外渲染遍次，因此玻璃采用局部静态表面，不做全屏动画；这属于设计约束，不代表本版本已有性能测量结论。
- [web.dev: Create OS-style backgrounds with backdrop-filter](https://web.dev/articles/backdrop-filter) recommends a fallback rather than an expensive blur polyfill. Our text-first alternative is a readable solid surface. / 官方工程资料建议提供降级而非昂贵模糊补丁；本项目以可读的实色表面降级。
- [W3C Understanding Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) distinguishes meaningful controls from decoration. Brand ornament is not a substitute for visible keyboard focus or control labels. / 装饰不替代可见键盘焦点或控件名称。

No new perceptual-research claim is made: translucency is an aesthetic enhancement, not evidence of improved usability. Contrast, keyboard access, responsive overflow, forced colors, and reduced motion require implementation testing. Screenshot quality alone does not establish accessibility conformance.

本次不宣称新的感知研究结论：透光是审美增强，并非可用性改善的证据。对比度、键盘操作、响应式溢出、强制颜色与减少动态效果需要实现级测试；截图漂亮不等于无障碍合规。

## Integration / 集成

Public React examples live at `/components/` and `/en/components/`. The showcase uses real exported components, local composer state, an actual documentation attachment link, and a reversible helpful-message toggle. Code examples use the shared Astro wrapper. New CSS layout rules are scoped to showcase classes and consume existing theme variables.

公开 React 示例位于 `/components/` 与 `/en/components/`；使用真实导出组件、本地编辑器状态、实际文档附件链接和可撤销的有帮助标记。代码示例使用共享 Astro 包装；新增布局 CSS 仅作用于展示类，沿用已有主题变量。
