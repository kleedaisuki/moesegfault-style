# v0.2.0 visual reset

Status: implemented. Supersedes the visual language of [v0.1.2-design.md](./v0.1.2-design.md); its notes on glass,
Markdown safety, and evidence limits still apply.

## Brief

Reset the whole visual language and look like modern technical tooling. The first pass kept the v0.1 palette; the
owner then opened color as well, asking only for a palette in Klee's colors. v0.1 read as a warm rounded
dashboard: large radii, soft stacked shadows, gradient emphasis, and a component set too small to build a real screen.

The v0.2 idea is **cute by default, careful by design**. A crimson coat, honey hair, clover, and leather give the
palette; a hairline grid, compact native controls, and monospace details give the discipline. The signature is a pixel
four-leaf clover on a crimson field that segfaults when pressed and springs back together. It uses original geometry
(an implicit heart curve folded by symmetry) and no game artwork.

## Rules

| Area | Rule | Reason |
| --- | --- | --- |
| Color | Crimson acts, honey highlights, clover confirms, leather writes and rules. Components read roles only. | One meaning per hue keeps a saturated palette calm. |
| Danger | Berry hue, outlined button. | The action role is red, so a filled red danger button would read as primary. |
| Brand surface | `data-moe-surface="brand"` remaps roles for a region. | Components inside need no inverse variants. |
| Action | One role, `--moe-action`, marks the next step. Crimson inside content is not decoration. | A single strong color only guides if it is rare. |
| Elevation | Hairline first, surface second, shadow last. Shadows belong to things that float. | Lines keep dense layouts legible in both themes. |
| Shape | Radii 3 / 6 / 8 / 12. | Nested corners stay concentric at control scale. |
| Density | Control heights 28 / 36 / 44, taller on coarse pointers. | Compact on desktop without shrinking touch targets. |
| Type | Geist for interface, Geist Mono for paths, numbers, and labels machines also read. | Numbers align, and identifiers look like identifiers. |
| Copy | No secondary label or description that layout, code, or the control already conveys. Keep one only when removing it would cause a mistake. | Less text makes structure do the explaining. |
| Motion | Still like an instrument at rest; fireworks only when touched. Geometry moves on shared springs. | Feedback should not delay work, and one physics reads as one material. |
| Controls | Native element first: `dialog`, `details`, `progress`, radio inputs. | The browser owns focus trapping, Escape, and form behavior. |

## Motion and art

**One spark, one physics.** Two damped springs drive all geometry. Tokens store only the damping ratio (0.78 `spring`,
0.5 `bounce`) in a DTCG `$extensions` entry; the builder samples the step response into `linear()` and emits it inside
`@supports`, after a `cubic-bezier` fallback.

**Reduced motion is data, not a branch.** Components use `var(--moe-spring)`, `var(--moe-bounce)`, or `var(--moe-exit)`,
each a duration and easing pair that is `0s linear` by default and gains its value under `no-preference`. Color fades
may use plain durations. `build.test.ts` rejects component geometry that bypasses the pairs.

**Enter on a spring, leave briskly.** Dialogs use `@starting-style` in and a short `allow-discrete` exit that never
intercepts clicks. Entrances animate only new things: the last message bubble, an appearing error, a drawn check.

**One indicator per group.** Tabs and segmented controls slide a single anchored pseudo-element. Without
`anchor-scope` each item paints its own indicator, as before.

**The clover is a simulation.** [`blast.ts`](../pages/src/lib/blast.ts) is pure: fixed 120 Hz step, seeded randomness,
units in cells and seconds. A shock is an expanding ring that acts on what it sweeps past, so cells, embers, and the
page-wide wave share one mechanism. Holding draws cells inward first (anticipation), and squares settle to the nearest
quarter turn because they cannot tell the difference. [`blast-stage.ts`](../pages/src/lib/blast-stage.ts) runs frames
only while something moves and is visible. Nothing loops at rest.

**Dither instead of opacity.** Embers, the halo, and section edges share one 8×8 Bayer matrix
([`dither.ts`](../pages/src/lib/dither.ts)). Pixels change density, not alpha, so the palette stays four colors wide.

**Page continuity is progressive.** Cross-document view transitions carry the clover and the nav mark between pages;
the theme change unfolds through a four-lobed clip. Unsupported browsers and reduced motion switch instantly.

Frame cost on 2026-11-22 (headless Chromium, 1920×1000, animation callback time during a full blast): median 0.6 ms,
p95 2.0 ms, at device pixel ratios 1 and 2; zero frames at rest.

## Evidence

- [Chang and Ungar 1993](https://bibliography.selflanguage.org/_static/animation.pdf): cartoon techniques such as
  anticipation make interface transitions easier to follow. Holding the clover before a blast applies it.
- [`linear()` springs](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/physics-based-easing),
  [cross-document view transitions](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document), and
  [anchor positioning](https://web.dev/blog/web-platform-01-2026): platform behavior and fallbacks. Firefox support for
  cross-document transitions is [still partial](https://caniuse.com/cross-document-view-transitions).

- [Tuch et al. 2012](https://research.google/pubs/pub38315/): low visual complexity with high prototypicality is judged
  most appealing. The site therefore uses conventional page structure and spends novelty on one element, the clover.
- [Reinecke et al. 2013](https://kgajos.seas.harvard.edu/papers/reinecke13aesthetics.pdf): perceived complexity predicts
  first impressions better than colorfulness. That is why structure was rebuilt first, and color
  changed second.
- [Geist design system](https://vercel.com/geist) and its [design notes](https://vercel.com/design.md): precedent for
  hairline structure, semantic roles, and restrained emphasis in developer tooling.
- [WAI-ARIA APG tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/): keyboard contract for `Tabs`.

These sources guide direction. They do not establish that this particular interface is more usable.

## Invariants worth keeping

**One KaTeX version.** Markup and stylesheet must come from the same release. `rehype-katex` pulled a second KaTeX, so
Markdown emitted 0.16 class names against 0.18 CSS. Markdown and standalone math now share `renderMath`, `katex` is
pinned exactly, and `math-contract.test.ts` checks the emitted classes, the identical markup, and the pin.

**Style longhands in foundations.** `text-wrap: pretty` is a shorthand that resets `text-wrap-mode`, which silently
overrides an ancestor's `white-space: nowrap`. Foundations set `text-wrap-style` only.

**Scroll at the owner.** Wide content (tables, code, display math) scrolls in its own box with `min-width: 0`. Table
cells use `overflow-wrap: break-word`, because `anywhere` lets a column collapse to one character.

**Both class forms share one rule.** `.moe-button--ghost` and `[data-variant="ghost"]` are joined with `:is()`, so the
legacy form cannot drift. The showcase suite compares their computed styles.

**Fonts stay opt-in.** `all.css` downloads no text fonts. `fonts.css` is generated from pinned packages with their
license files beside them.

## Compatibility

No export, prop, class name, CSS variable, import path, or published release was removed. The 0.1 color primitives keep
their values with DTCG `$deprecated`; semantic roles point at the Klee palette. Defaults for radius, shadow,
motion duration, control height, and font stacks changed, which is why this is a minor release in `0.x`. Consumers that
need the old look can pin `/v0.1.2/` or override the matching variables.

## Verification

- Unit: frozen 0.1 primitives, danger and action hue separation, font opt-in, KaTeX contract, control semantics.
- Browser (Chromium desktop, WebKit mobile): both themes, WCAG AA text contrast on the showcase, page overflow,
  keyboard focus, forced colors (Chromium only), reduced motion, legacy class parity.
- Motion: simulation converges exactly, is independent of refresh rate, and stays bounded after a pause; spring
  overshoot matches its damping ratio; reduced motion zeroes every pair; indicators track their selection.
- Not covered: real assistive technology, physical devices, native input methods, low-end GPU profiling.
